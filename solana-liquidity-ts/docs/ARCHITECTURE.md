# 🏗️ Архитектура Solana Liquidity Aggregator

## Обзор системы

Solana Liquidity Aggregator - это модульная система для агрегации ликвидности из различных DeFi протоколов Solana. Система построена на принципах микросервисной архитектуры с использованием NestJS фреймворка.

## Архитектурные принципы

### 1. Модульность
- Каждый протокол изолирован в отдельном модуле
- Общие компоненты вынесены в shared модули
- Четкое разделение ответственности

### 2. Масштабируемость
- Горизонтальное масштабирование через Docker
- Кэширование для оптимизации производительности
- Асинхронная обработка данных

### 3. Надежность
- Автоматические фолбэки для RPC запросов
- Обработка ошибок на всех уровнях
- Мониторинг здоровья сервисов

### 4. Расширяемость
- Унифицированные интерфейсы для протоколов
- Фабрика протоколов для легкого добавления новых
- Плагинная архитектура

## Компоненты системы

### 1. Config Module
**Назначение**: Централизованное управление конфигурацией

**Компоненты**:
- `ConfigService` - сервис конфигурации
- Переменные окружения
- Валидация настроек

**Взаимодействие**:
- Предоставляет конфигурацию всем модулям
- Инжектируется как глобальный сервис

### 2. Common Module
**Назначение**: Общие компоненты, используемые во всей системе

**Компоненты**:
- **Types**: Интерфейсы и типы данных
- **Utils**: Математические утилиты и работа с ключами
- **RPC**: Пул RPC эндпоинтов
- **Cache**: Кэширование с Redis

**Взаимодействие**:
- Используется всеми модулями
- Предоставляет базовую функциональность

### 3. Database Module
**Назначение**: Работа с базой данных PostgreSQL

**Компоненты**:
- `PrismaService` - ORM клиент
- `PoolsRepository` - репозиторий пулов
- `QuotesRepository` - репозиторий котировок

**Взаимодействие**:
- Предоставляет доступ к данным
- Обеспечивает транзакционность

### 4. Pools Module
**Назначение**: Модули для работы с различными протоколами

**Структура**:
```
pools/
├── common/              # Общие интерфейсы
│   ├── liquidity-pool.interface.ts
│   └── discovery.interface.ts
├── raydium-amm/         # Raydium AMM
├── raydium-clmm/        # Raydium CLMM
├── orca-whirlpool/      # Orca Whirlpool
└── meteora-dlmm/        # Meteora DLMM
```

**Каждый протокол содержит**:
- `*.module.ts` - модуль NestJS
- `*.service.ts` - бизнес-логика
- `*.layout.ts` - парсинг данных

### 5. Indexer Module
**Назначение**: Автоматическая индексация пулов

**Компоненты**:
- `IndexerService` - основной сервис индексации
- Периодическое обновление данных
- Мониторинг здоровья

**Взаимодействие**:
- Использует сервисы протоколов
- Обновляет базу данных
- Предоставляет метрики

### 6. Quote Engine Module
**Назначение**: Движок котировок и агрегации

**Компоненты**:
- `QuoteService` - получение котировок
- `AggregatorService` - агрегация с стратегиями

**Стратегии агрегации**:
- `best_output` - максимальный выход
- `lowest_fee` - минимальная комиссия
- `lowest_price_impact` - минимальное влияние на цену
- `weighted_average` - взвешенное среднее

### 7. API Module
**Назначение**: REST API для внешнего взаимодействия

**Компоненты**:
- `PoolsController` - API для пулов
- `QuotesController` - API для котировок
- `UnifiedController` - унифицированный API
- DTO для валидации

## Потоки данных

### 1. Индексация пулов
```
RPC Endpoints → Protocol Services → Database
     ↓              ↓              ↓
  Raw Data → Parsed Pools → Stored Pools
```

### 2. Получение котировок
```
API Request → Quote Service → Protocol Services → Aggregator → Response
     ↓            ↓              ↓              ↓           ↓
  Validation → Pool Search → Quote Calculation → Best Quote → JSON
```

### 3. Кэширование
```
Request → Cache Check → Cache Hit/Miss → Service Call → Cache Update
   ↓          ↓            ↓              ↓            ↓
  API → Redis → Cached Data → Database → Updated Cache
```

## Паттерны проектирования

### 1. Repository Pattern
- Абстракция доступа к данным
- Изоляция бизнес-логики от данных
- Легкое тестирование

### 2. Factory Pattern
- Создание экземпляров протоколов
- Унифицированный интерфейс
- Легкое добавление новых протоколов

### 3. Strategy Pattern
- Различные стратегии агрегации
- Легкое переключение алгоритмов
- Расширяемость

### 4. Observer Pattern
- События индексации
- Уведомления об изменениях
- Логирование
